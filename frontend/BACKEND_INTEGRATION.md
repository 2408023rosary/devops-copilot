# Frontend integration contract

The delivered app is a complete interactive frontend. Demo mode persists sample records in this browser and simulates network delay. It does not call an AI model, monitor Kubernetes, send operating-system notifications, or execute remediation.

## Select a data source

Copy `.env.example` to `.env.local`, then restart Vite:

```ini
VITE_API_MODE=http
VITE_API_BASE_URL=http://localhost:8000/api
```

Leave `VITE_API_MODE=demo` to run without a backend. Production environment values are compiled into the bundle when `npm run build` runs. Never store private API keys in `VITE_*` variables.

All backend calls are isolated in `src/services/api.js`. Components use `src/state/WorkspaceProvider.jsx`; they do not call fetch directly. If your server has a different URL or payload shape, adapt this file while preserving its public method return values.

## Transport behavior

- JSON request/response bodies; `Accept: application/json`.
- Cookies are included (`credentials: include`). Configure server CORS for the exact frontend origin and credentials if using another origin. Authentication, authorization, CSRF controls, server validation, and tenant scoping belong to your backend. No login UI is included because no authentication contract was supplied.
- Non-2xx responses produce a visible error and a retry opportunity. The UI preserves existing workspace data if refresh fails.
- Requests time out after 30 seconds. Message requests accept AbortSignal for Stop and page-navigation cancellation. Cancellation stops waiting in the browser; the server may already have committed work. Honor `requestId` to prevent duplicates on retry.
- Messages are complete responses, not a token stream. The frontend shows typing activity until the response arrives. Add SSE/WebSocket support inside the adapter if your backend streams tokens.
- Mutations return their authoritative updated record. Deletions may return 204. IDs and timestamps are assigned by the backend in HTTP mode.

## Endpoints

| Method | Endpoint                      | Request body                                          | Response                                                |
| ------ | ----------------------------- | ----------------------------------------------------- | ------------------------------------------------------- | ------ | ---------------- |
| GET    | `/workspace`                  | —                                                     | Workspace                                               |
| PATCH  | `/incidents/:id`              | `{status}` or `{note}`                                | Updated Incident                                        |
| POST   | `/incidents/:id/analysis`     | —                                                     | Incident with analysis and timeline event               |
| POST   | `/conversations`              | `{incidentId: string                                  | null, memoryId: string                                  | null}` | New Conversation |
| POST   | `/conversations/:id/messages` | `{text, requestId}`                                   | Conversation containing new user and assistant messages |
| PATCH  | `/conversations/:id`          | `{title}`                                             | Updated Conversation                                    |
| DELETE | `/conversations/:id`          | —                                                     | 204                                                     |
| DELETE | `/conversations`              | —                                                     | 204                                                     |
| PATCH  | `/settings`                   | Partial Settings                                      | Complete updated Settings                               |
| POST   | `/memories`                   | `{incidentId, service, title, rootCause, resolution}` | New Memory                                              |
| DELETE | `/memories/:id`               | —                                                     | 204                                                     |
| DELETE | `/memories`                   | —                                                     | 204                                                     |

Endpoints are relative to `VITE_API_BASE_URL`. Demo reset is deliberately unavailable in HTTP mode.

## Data model

A complete example is generated by `createDemoWorkspace()` in `src/data/demo.js`.

```ts
type IncidentStatus = 'investigating' | 'monitoring' | 'resolved'
type Severity = 'critical' | 'warning'
type Settings = {
  notifications: boolean // Frontend success toasts; errors always shown.
  autoAnalyze: boolean // Analyze an opened incident if analysis is missing.
  showLogs: boolean // Dashboard/chat evidence panels.
  rememberChats: boolean // Persistence policy for NEW conversations.
  memoryEnabled: boolean
  animations: boolean
}
type Service = {
  id: string
  name: string
  status: 'healthy' | 'warning' | 'critical'
  uptime: string
  description: string
  replicas: string
  region: string
}
type Incident = {
  id: string
  service: string
  title: string
  severity: Severity
  status: IncidentStatus
  error: string
  createdAt: string
  description: string
  logs: string[]
  rootCause: string
  recommendations: string[]
  notes: { id: string; text: string; at: string }[]
  timeline: { text: string; at: string }[]
  analysis: null | { summary: string; recommendations: string[]; generatedAt: string }
}
type Conversation = {
  id: string
  title: string
  incidentId: string | null
  memoryId: string | null
  persisted: boolean
  createdAt: string
  updatedAt: string
  messages: {
    id: string
    role: 'user' | 'assistant'
    text: string
    at: string
    requestId?: string
  }[]
}
type Memory = {
  id: string
  incidentId: string
  service: string
  title: string
  similarity: number | null
  createdAt: string
  rootCause: string
  resolution: string
}
type Workspace = {
  settings: Settings
  services: Service[]
  incidents: Incident[]
  conversations: Conversation[]
  memories: Memory[]
}
```

Use ISO 8601 timestamps. All array properties must exist, even when empty. Validate text, enums, ownership, and input limits on the server. The UI limits messages to 4,000 characters, notes/resolutions to 2,000, chat titles to 100, and root causes to 300.

## Behavioral details

- Changing incident workflow status does not modify service telemetry. A resolved ticket is not proof that a service is healthy.
- Set `persisted` when a conversation is created, based on `rememberChats`. Existing chats keep their original persistence policy. A backend must enforce the equivalent session-only retention policy for private conversations.
- The first sent question becomes the demo conversation title. Renaming a conversation preserves messages.
- The demo message endpoint deduplicates on `requestId`; the HTTP server should do the same. If a write commits but the response is lost, the client retries with the same key.
- Context is fixed per conversation. Start a new conversation to use another incident or memory.
- Memory scores in the seed data are explicitly labeled sample reference scores. New saved investigations are unscored. There is no vector search implemented.
- Saving memory requires the user to enter a verified cause and resolution. Suggested actions are not automatically recorded as successful remediation.
- Demo storage key: `nexus-workspace-v2`. Session-only chats remain in the current tab's memory but are excluded from localStorage. This version starts a separate demo workspace from the previous prototype's legacy storage keys.

## Tests

`npm run test:api` starts a Vite instance in HTTP mode and intercepts backend responses to verify load failures, retries, message idempotency, and failed-refresh data preservation. This verifies the frontend adapter, not an actual backend deployment.
